# Anonymity Audit

This document records what was checked before submission and what the checks found. It is generated by hand from the results of `code/91_build_supplementary_zip.py`, which performs these checks programmatically on every build and refuses to write an archive that fails any of them.

## What is checked

1. **`main.tex`'s author block.** The working copy of `main.tex` carries the real author's name, email, and affiliation (required so the same source compiles correctly under `tmlr.sty`'s `[accepted]`/`[preprint]` modes after review). Before archiving, `code/91` replaces this block in memory with `Anonymous Author(s)` / `anonymous@anon.invalid` / `Affiliation withheld for double-blind review`, and aborts the build if the expected author-block pattern is not found (i.e., it fails closed, not open).
2. **Every text-suffixed file in the archive** (`.py .md .tex .txt .json .yaml .yml .sty .bst .cfg .toml .sh .gitignore`) is scanned for: absolute macOS/Linux/Windows home paths (which leak a username), email addresses, the institution name, and the author's name in several forms. Third-party vendored code and LaTeX class files are exempted, since those carry their own upstream maintainers' identities, which is expected and not a leak.
3. **The zip archive comment field.** This is the vector a previous revision missed — a git commit hash was once stored in the archive's comment field, which does not appear in `unzip -l` or any normal file listing. The build now always writes an empty comment and asserts this after writing.
4. **Retracted numbers.** Independently of anonymity, the same script scans every archived text file for numbers this paper has explicitly withdrawn (e.g., the retracted "48.6×" multiplier, an earlier retracted comparative claim), so a stale copy cannot ship silently.
